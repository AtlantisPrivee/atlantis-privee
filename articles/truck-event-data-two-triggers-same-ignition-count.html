Two Truck Event Records Show the Same Ignition Count

✍️ Atlantis Editorial 📅 November 7, 2026 ⏱ 2 min read

A truck download has two event entries, and both show the same ignition count. First check which field the number represents. A count sampled at an event and a count reported at download can answer different questions. The meaning depends on the recorder, software and data definition.

Identify what produced each entry

Ask the examiner for the module type, software version, native download and data dictionary. Make one row for each event with its label, trigger threshold, recorded time, distance or odometer, ignition field and the length of the saved window. Mark fields reported once for the download separately from those stored for each event.

The federal light-vehicle EDR standard distinguishes ignition cycle at the crash from ignition cycle at download. Its application is limited to specified vehicles. For a heavy truck's engine module, use that model's report and definitions to determine which fields it provides and how it sampled them. NHTSA's EDR rule and field definitions

Use the trigger definitions before lining up the traces

An NTSB report on a Detroit Diesel DDEC IV download distinguished the hard-brake records from the last-stop record. Its described hard-brake trigger used a configured deceleration threshold. The last-stop trigger used a transition from motion to a stop or ignition shutoff under the recorder's conditions. In that file, the most recent hard-brake entry and the last-stop entry were only seconds apart. The labels and recorded windows make the difference important. NTSB event data factual report

In another NTSB download of a DDEC IV, two hard-brake records were retained from a date months before the accident under investigation. That is a reason to ask which stored events belong to the crash being reviewed. NTSB electronic control module factual report

Ask for the sequence the data can support

If both counters were actually sampled at the trigger and the manufacturer confirms how the count increments, the matching numbers may help place both events within the same ignition cycle. Establish the order and any relationship to an impact using timestamps, event windows, vehicle motion and another source. Flag an uncertain clock setting. Use the Insurance Claim Timeline Builder to keep the module and external sources distinct.
